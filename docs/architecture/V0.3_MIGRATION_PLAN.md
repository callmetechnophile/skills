# V0.3 Phased Migration Plan: Node.js Baseline to Rust Core

## 1. Migration Strategy & Safeguards

The migration from Node.js (V0.2) to Rust (V0.3) will be conducted across 5 discrete, sequential phases.
Under no circumstances will the Node.js baseline be removed or broken until 100% functional and CLI parity has been proven through automated cross-engine regression tests.

```text
+-----------------------------------------------------------------------------------+
| PHASE A: Rust Workspace Foundation & Toolchain Setup                              |
| - Cargo.toml workspace, rust-toolchain.toml, CI pipeline, tracing, CLI skeleton   |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| PHASE B: Core Task Intelligence & Triage Engine                                   |
| - task-intelligence, issue-analyzer, complexity heuristics, schema validation      |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| PHASE C: Skill Engine (Discovery, BM25 Ranking, Security, Activation)            |
| - Tantivy index, SkillsDirectory sync, static scanner, activation planner        |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| PHASE D: Orchestration, Dependency DAG & Runtime Adapters                         |
| - petgraph scheduler, wave builder, Mode C fallback, agent adapters              |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| PHASE E: Parity Validation, Benchmarking & Node.js Decommissioning                |
| - Differential parity test suite, performance benchmarks, final release tag       |
+-----------------------------------------------------------------------------------+
```

---

## 2. Phase-by-Phase Roadmap

### Phase A — Rust Workspace Foundation & CI Toolchain
- **Deliverables:**
  - Root `Cargo.toml` configuring workspace members.
  - `rust-toolchain.toml` targeting Rust stable `1.80+`.
  - Shared domain error types using `thiserror`.
  - Base `router-cli` Clap binary skeleton with `--version` and `--help`.
  - GitHub Actions CI workflow adding `cargo test`, `cargo clippy`, and `cargo fmt`.
- **Exit Criteria:** `cargo test` and `cargo check --workspace` pass on Ubuntu, macOS, and Windows.

### Phase B — Core Task Intelligence & Triage Parity
- **Deliverables:**
  - Crates: `task-intelligence` and `issue-analyzer`.
  - Port `TaskNormalizer` (intent verbs and domain token extraction).
  - Port `ComplexityAnalyzer` (0–10 rubric, scope, coupling, uncertainty, risk, parallelism).
  - Port `IssueSorter` with JSON schema enforcement using `jsonschema`.
  - Differential unit tests asserting identical classification and work-package outputs against V0.2 fixtures.
- **Exit Criteria:** Zero discrepancy on all 33 test inputs between Node.js and Rust triage outputs.

### Phase C — Skill Engine (Discovery, Ranking, Security & Activation)
- **Deliverables:**
  - Crates: `skill-registry`, `skill-discovery`, `skill-ranking`, `skill-security`, `skill-activation`.
  - Implement `LocalRegistry` reading `skills/` and `catalog/manifest.json`.
  - Implement Tantivy-backed in-memory / on-disk BM25 lexical retrieval and n-gram vectorizer.
  - Port `DirectoryResolver` using `reqwest` and GitHub Git tree API.
  - Port `TrustScanner` and `TrustPolicy` with identical AST/regex rule catalog.
  - Implement `ActivationPlanner` with SHA-256 integrity verification.
- **Exit Criteria:** All 7 E2E discovery, ranking, security rejection, and activation test scenarios pass in Rust.

### Phase D — Orchestration, DAG Scheduling & Runtime Adapters
- **Deliverables:**
  - Crates: `agent-orchestrator`, `runtime-adapters`, `execution-engine`.
  - Implement `petgraph`-based topological sort, cycle detection, and wave scheduling.
  - Implement Mode A (single), Mode B (multi-agent wave schedule), and Mode C (honest sequential fallback).
  - Port runtime adapters for Antigravity, Claude Code, and Codex.
- **Exit Criteria:** Cyclic dependencies correctly rejected; Mode C fallback correctly logged when subagent bridge is absent.

### Phase E — Full Parity Validation, Benchmarking & Baseline Retirement
- **Deliverables:**
  - Complete CLI commands: `sort`, `route`, `find`, `sync:catalog`, `install:skill`, `list:skills`, `verify:skills`, `update:skills`.
  - End-to-end parity test runner comparing outputs of `node src/router.mjs` vs `cargo run --`.
  - Publish performance benchmark report (cold start, indexing throughput, memory usage).
  - Safely archive Node.js routing scripts into `legacy/` or decommission them completely.
  - Update `AGENTS.md` and `README.md` for V0.3 binary usage.
- **Exit Criteria:** 100% parity across all CLI commands and schemas; benchmarks meet P95 targets; production release approved.

---

## 3. Rollback & Contingency Plan

If any Rust crate encounters unexpected blockers or platform compilation errors during Phases A–D:
1. The stable V0.2 Node.js implementation remains untouched and completely operational on `main`.
2. Work continues exclusively on `feat/rust-core-v0.3`.
3. No Node.js scripts or tests will be altered or deleted until Phase E passes all acceptance criteria.

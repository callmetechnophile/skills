# V0.3 Target Rust Architecture Specification

## 1. Architectural Mission & Principles

The objective of V0.3 is to migrate the core routing, discovery, ranking, security, and orchestration engine from Node.js to a native, high-performance, strongly-typed Rust workspace.

### Core Principles
1. **Single Authoritative Engine:** Rust becomes the primary engine; Node.js scripts will be fully retired upon parity demonstration.
2. **Zero Metadata Drift:** Existing `SKILL.md` frontmatter, `.installed-skills.json` schemas, and `catalog/` files remain fully compatible.
3. **Deterministic & Offline-First:** Core operations (triage, discovery, BM25 ranking, static security scanning, and Mode C scheduling) must operate 100% offline with zero required network calls.
4. **Compile-Time Safety & Zero-Cost Concurrency:** Memory safety, strict ownership semantics, and thread-safe read-only operations without unnecessary mutex contention.
5. **Single Self-Contained Binary:** Produces `skill-router` (or `skills-router.exe` on Windows) with sub-15ms cold start.

## 5. Technology Stack Selection & Freezing

| Component | Selected Crate | Version | Evaluation & Rationale |
|---|---|---|---|
| **Async Runtime** | `tokio` | `1.38+` | Industry standard, robust multi-threaded async execution, timeout support. |
| **HTTP Client** | `reqwest` | `0.12+` | Pure Rust TLS (`rustls`), connection pooling, JSON deserialization. |
| **Serialization** | `serde`, `serde_json`, `serde_yaml` | `1.0+` | Zero-copy deserialization, handles existing JSON schemas and YAML frontmatter. |
| **CLI Parser** | `clap` (derive) | `4.5+` | Compile-time CLI generation with autocompletion and robust flag handling. |
| **Error Handling** | `thiserror`, `anyhow` | `1.0+` | Strongly typed enum errors for libraries, contextual errors for CLI. |
| **Logging & Tracing** | `tracing`, `tracing-subscriber` | `0.1+` | Structured span-based diagnostic logging with JSON/terminal formatting. |
| **Lexical Search / BM25**| `tantivy` | `0.22+` | Blazing fast, pure-Rust Lucene alternative for in-memory or on-disk inverted indexes. |
| **DAG & Graph Scheduling**| `petgraph` | `0.6+` | Battle-tested graph data structures, topological sort, cycle detection. |
| **Cryptography** | `sha2` | `0.10+` | Standard NIST SHA-256 implementation with constant-time security features. |
| **Regex & Pattern Engine**| `regex` | `1.10+` | Linear-time regex engine immune to ReDoS attacks. |
| **Schema Validation** | `jsonschema` | `0.18+` | Full JSON Schema draft-7 / 2020-12 compliance in Rust. |
| **Local Embeddings** | `ort` (ONNX Runtime) | Optional / Feature-gated | Pluggable embedding inference; fallback to fast character 3-gram cosine similarity. |

## 6. Concurrency & Performance Targets

1. **Cold Start:** Cold CLI invocation execution time `< 15ms`.
2. **Triage Throughput:** `< 5ms` for deterministic heuristics; zero heap fragmentation.
3. **In-Memory Search:** `< 20ms` BM25 lookup across 10,000 skills via Tantivy.
4. **Memory Footprint:** Resident Set Size (RSS) `< 25MB` during normal CLI queries.
5. **Binary Size:** Stripped release binary `< 12MB` on Linux x86_64 and Windows x86_64.
